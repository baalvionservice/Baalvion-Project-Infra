# GTI admin panels and live sites — QA report, 2026-10-13

Tested as an outsider on the live sites, and signed in on a local copy of `main` (fresh database,
26 role accounts). Nothing here was tested against production while signed in.

## Summary
- **Nothing crashed.** All 63 governance/oversight pages load for a super admin; zero JavaScript errors.
- **No admin panel is exposed to an outsider** (110 URLs across 21 live domains).
- **Role gates work for the common roles:** buyer, seller, agent, organisation owner and logistics
  coordinator open none of the 24 sensitive panels; the national regulator is confined to 6 of 63.
- **The big problem is behind the screens:** many panels are not backed by a real system (H1–H2).

## Findings

### High
**H1. 62 of the 97 backend endpoints the GTI screens use have no real route.** They fall into the
generic JSON bucket: any logged-in user can create, read and delete any JSON in it, with no
validation, no state machine and no role check. Verified two ways: 14 of them (settlements,
trade_finance_instruments, letters_of_credit, invoice_financing, contracts, approvals,
sanctions_signals, risk_signals, users, webhooks, pam_sessions, escalation_cases, directives, ports)
answer identically to a made-up name, and a buyer account POSTed to letters_of_credit, settlements,
contracts and approvals and got 201 each time. Data is isolated per organisation, so this is
about integrity, not cross-customer leakage. The screens look functional; nothing real happens
behind them. *Method caveat:* the 62 comes from a static scan of route registrations; the 14 above
were confirmed live.
*Recommendation:* decide which of these must be real before launch (settlements, letters of credit,
trade finance, contracts, approvals first), give those typed routes with role checks, and for the
rest show an honest "not available yet".

**H2. Governance policies do not govern anything, and any user can write them.** Full detail and a
plan in `GOVERNANCE-POLICY-STORE-SCOPE.md`. A buyer created a global priority-999 "allow" policy.

### Medium
**M1. Several admin panels are stubs.** The Audit Ledger always shows nothing (its data source
returns an empty list); the Permissions matrix has no backend and saves nothing; the
Organizations "intervention" button writes a JSON document and has no effect.
**M2. Role questions for you to confirm.** `platform_auditor` opens all 24 sensitive panels, and
through H1 could also write. `bank_admin` opens the Permissions and Organizations panels. The
regulator opens the Policies registry and Audit Logs. Seven non-platform roles open Audit Logs
(harmless today because it is empty, wrong once it is real).
**M3. Four live sites are down:** `connect.baalvion.com` and `dashboard.baalvion.com` have expired
certificates (2 Sep, 25 Aug) and DNS pointing at Vercel, which returns 404; `controlthemarket.com`
has no address record; `help.baalvion.com` has no DNS at all. All four are still in the site registry.
**M4. The role-account seed script cannot run on a freshly migrated database** (member-role check
rejects roles like `buyer`); it only worked where that check had been relaxed by hand.

### Fixed in this round
**Disputes panel** (PR #770): requested `status=OPEN` (backend answers 400), so it showed "No active
disputes" while disputes were open, and invented a 350,000 value and buyer/seller names.

### Low
- Soft 404s: `marketunderworld.com/admin/*` and `proxy.baalvionstack.com/admin/*` return HTTP 200 with a
  "404 Oops" page.
- `newaiskillsteam.baalvion.com/admin*` throws React error #441 on every admin URL (login still shows).
- Static claims shown as facts: "fraud engine is currently checking 48 active nodes. Zero critical
  failures detected", "All institutional profiles verified".
- Slow first loads on the dev server (`/governance` 16 s); production timing not measured.
- Some panels redirect: 7 `/oversight/*` pages forward to their `/governance/*` twins, so GTI has
  about 50 distinct admin panels, not 57.

## Coverage — what this did NOT test
- Writing through the forms (create/edit/approve/delete flows) beyond the disputes panel.
- 14 of the 16 roles on all 63 panels (they were tested on the 24 most sensitive ones).
- The orders and escrow panels (the order service was not running locally); the Onboarding panel
  (needs a platform-owner organisation account; the super admin got 403).
- Production while signed in. A tester with a staging account should repeat the matrix there.
- The central admin console (190 pages) and the other sites' admin areas.
